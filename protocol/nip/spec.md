# NeuroCore Intent Protocol (NIP) v0

**This file is normative.** `nip.h`/`nip.c`, `nip.py` and `vectors.json` follow it. If they disagree with this file, they are wrong. Source: ROADMAP §8.1.

## 1. Frame

16 bytes. All multi-byte fields are **little-endian**.

| Offset | Size | Field | Type | Valid values |
|---|---|---|---|---|
| 0 | 2 | magic | u16 | `0x4E50` (on the wire: `50 4E`) |
| 2 | 1 | version | u8 | `0` |
| 3 | 1 | seq | u8 | 0–255, +1 per frame sent, wraps 255 → 0 |
| 4 | 4 | t_ms | u32 | sender uptime in ms, wraps |
| 8 | 1 | intent | u8 | see §2 |
| 9 | 1 | level | u8 | 0–3 (speed or analog level) |
| 10 | 1 | confidence | u8 | 0–255 |
| 11 | 1 | flags | u8 | see §3; bits 5–7 must be 0 |
| 12 | 2 | reserved | u16 | `0` |
| 14 | 2 | crc16 | u16 | CRC over bytes 0–13 (§4) |

## 2. Intents

| Value | Name | Meaning |
|---|---|---|
| 0 | STOP | Stop now. Adapters brake / release / hover. |
| 1 | HOLD | Keep the current mode at `level`. |
| 2 | FWD | Forward gear at `level`. |
| 3 | REV | Reverse gear at `level`. |
| 4 | LEFT | Steer left (held), keep moving at `level`. |
| 5 | RIGHT | Steer right (held), keep moving at `level`. |
| 6 | MODE_NEXT | Device-specific mode change. |
| 7 | AUX_A | Device-specific auxiliary action. |
| 8 | AUX_B | Device-specific auxiliary action. |

## 3. Flags

| Bit | Name |
|---|---|
| 0 | calibrated |
| 1 | artifact |
| 2 | channel_bad |
| 3 | latched_stop |
| 4 | test_mode |
| 5–7 | reserved, must be 0 |

## 4. CRC

CRC-16/CCITT-FALSE: width 16, poly `0x1021`, init `0xFFFF`, no input or output reflection, xorout `0x0000`. Check value: CRC of ASCII `123456789` is `0x29B1`. Computed over bytes 0–13, stored little-endian at bytes 14–15.

## 5. Decoding (normative order)

A receiver checks, in this order, and stops at the first failure. Both codecs must report the same status for the same bytes.

| # | Check | Status | Code |
|---|---|---|---|
| 1 | length is exactly 16 | `LEN` | 1 |
| 2 | magic is `0x4E50` | `MAGIC` | 2 |
| 3 | version is 0 | `VERSION` | 3 |
| 4 | CRC matches | `CRC` | 4 |
| 5 | intent ≤ 8 | `INTENT` | 5 |
| 6 | level ≤ 3 | `LEVEL` | 6 |
| 7 | flags bits 5–7 are 0 | `FLAGS` | 7 |
| 8 | reserved is 0 | `RESERVED` | 8 |

Success is `OK` (code 0). v0 decoding is **strict**: any failure means the frame is **not valid**, and an invalid frame never feeds the link watchdog (§7). An encoder refuses to build a frame that would fail checks 5–8.

## 6. Sequence numbers

`seq_is_newer(candidate, last)` is true when `(candidate − last) mod 256` is in 1..127 (serial-number arithmetic, RFC 1982 style). A difference of 0 is a duplicate; 128..255 is old.

## 7. Timing and safety (docs/safety.md S1)

- The sender transmits at **25 Hz** even when nothing changes (heartbeat).
- Every adapter enters its safe state if it has received **no valid frame for 300 ms**. Drone: hover or land. Car: coast then brake.
- A frame is valid only if it decodes `OK`. Adapters may additionally ignore valid frames that are not newer (§6); ignored frames do not feed the watchdog.

## 8. Transports

ESP-NOW (car, drone bridge), BLE (gamepad), Wi-Fi/MQTT (home), UART/SPI (FPGA). The 16-byte frame is carried unchanged; any transport framing is defined per transport.

## 9. Golden vectors

`vectors.json` is generated by `python -m protocol.nip.gen_vectors`, which also writes `tests/c/nip_vectors.h`. A test fails if either file is out of date. Both codecs must pass every vector.
